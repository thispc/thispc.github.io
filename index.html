Projects

Four systems built and run in 2026. Each one has a rule that is enforced in code rather than in a prompt: what may ship, what the model may see, what may be sent.

  • devteam

    AI agents write the software; a separate checker decides if it is good enough

    thispc/devteam

    Each module is defined by a contract: the functions it must expose and what they take and return. An agent writes the code, the code is built in a container with no network, twice, and it is judged by tests the agent never saw. Only then does it ship.

    The hard part: once an agent has read the tests it is graded by, those tests stop telling you anything. The hidden ones caught real bugs the visible suite had passed.

    Ran end to end with no human intervention: an AI manager derived the contracts, delegated the work and shipped every module through the checker. A content-addressed cache turns a repeat build into a 45 ms hit instead of a 6.3 s rebuild.

    • Node.js
    • TypeScript
    • Docker
    • Claude Agent SDK

  • HumanHands

    An assistant that operates a Mac the way a person does

    thispc/humanhands

    It reads the screen through the macOS accessibility tree instead of screenshots, so the coordinates are exact and no image of your screen leaves the machine. Then it moves the real cursor along a human path and types at human speed, in any application.

    The hard part: keeping passwords away from the model without making it useless. They stay in the Keychain and reach the model only as placeholders, filled in at the last instant after the site has been checked.

    Native Swift across 10 SwiftPM targets. 135 tests, run off-device.

    • Swift
    • SwiftUI
    • Accessibility API
    • CoreGraphics
    • Keychain
    • Claude

  • Personal email agent

    Reads my mail and messages, drafts replies, sends nothing without my tap

    thispc/nanoclaw

    Built on the open-source NanoClaw runtime, small enough to audit in an evening. It answers from my phone over iMessage, keeps what it knows about me in plain files I can read and correct, and runs as three background services on my own hardware.

    The hard part: anyone who emails me can try to talk the agent into something. So the part that reads mail has no tools, the part with tools never sees raw mail, and every outgoing message stops at a one-tap approval that sends exactly the draft I saw.

    Three daemons, running 24/7. iMessage channel and plain-file knowledge base added to the upstream runtime.

    • TypeScript
    • Node.js
    • Claude Agent SDK
    • Docker
    • SQLite

  • trader-automata

    One trade decision, mirrored across many brokerage accounts

    thispc/trader-automata

    What the copy-trading desks in India run: one signal fanned out to many accounts at once. It turned out to be a distributed-systems and compliance problem rather than a trading one. What matters is that every order is traceable and the thing stays up.

    The hard part: partial failure is normal. One account rejecting an order must never undo another account's fill, so every child order carries an idempotency key and every step is appended to a ledger, never overwritten.

    Paper, connect and live stages. Deployed behind HTTPS on a static IP with a live Angel One account. 33 tests.

    • Python
    • FastAPI
    • SQLAlchemy
    • Next.js
    • TypeScript
    • Docker
