Projects

      
Four agent systems built in 2026. Each one has a security boundary that is enforced in code rather than in a prompt.

      
    
        
  • 
          
    
            
    
              
    devteam
    
              
    Contract-bound microbot harness for agent-written software
    
            
    
            thispc/devteam
          
    
          
    Every module is a contract (interface, tests, pinned toolchain) hashed into its identity. Agent-written code is admitted only after it passes in a network-less Docker container, run twice with transcripts diffed, plus held-out tests the author never sees.
    
          
    What is hard: once an agent has read the tests it is judged by, those tests stop being an unbiased signal. The held-out vaults caught real bugs the visible suite had passed.
    
          
    356 commits in an end-to-end trial with zero human interventions. Cache hit 45 ms, rebuild 6.3 s.
    
          
    • Node.js
    • TypeScript
    • Docker
    • Claude Agent SDK
    
        
    • 
        
  • 
          
    
            
    
              
    HumanHands
    
              
    Native macOS computer-use agent
    
            
    
            thispc/humanhands
          
    
          
    Perceives the screen through the macOS Accessibility tree (local, pixel-exact, no screenshots sent to the model), reasons with Claude, and drives the real cursor along human-like paths with human typing cadence.
    
          
    What is hard: keeping secrets out of the model structurally. Credentials live in the Keychain and reach the model only as placeholders substituted at the last instant. A domain-verified gate refuses to type a secret on an unconfirmed site.
    
          
    Fully native Swift across 10 SwiftPM targets. 135 tests run off-device.
    
          
    • Swift
    • SwiftUI
    • Accessibility API
    • CoreGraphics
    • Keychain
    • Claude

  • 
          
    
            
    
              
    Personal email agent
    
              
    A fork of the open-source NanoClaw runtime
    
            
    
            thispc/nanoclaw
          
    
          
    A tool-less reader model is the only component that touches raw email. The acting agent sees only sanitised digests, and every outbound action stops at a one-tap approval that sends exactly the pre-created draft, enforced in host code.
    
          
    What is hard: any text the agent reads can carry instructions. The defence lives in the data flow: the component that reads mail has no tools, and the component with tools never reads mail.
    
          
    Added an iMessage channel and a plain-file knowledge base (16k lines). Three daemons, 24/7 on my own hardware.
    
          
    • TypeScript
    • Node.js
    • Claude Agent SDK
    • Docker
    • SQLite

  • 
          
    
            
    
              
    trader-automata
    
              
    Multi-account order fan-out platform
    
            
    
            thispc/trader-automata
          
    
          
    Mirrors one trade decision across many brokerage accounts at once. A pluggable broker layer on official SDKs, idempotent fan-out over an append-only event-sourced ledger, role-based multi-tenant auth, and Fernet-encrypted credentials with TOTP.
    
          
    What is hard: partial failure is normal. One account's rejection must never roll back another's fill, so every child order carries an idempotency key and every transition is an appended event.
    
          
    Paper, connect and live stages. Deployed behind HTTPS on a static IP with a live Angel One account. 33 tests.

    • SQLAlchemy
